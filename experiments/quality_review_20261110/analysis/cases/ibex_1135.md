## 原始 HWE 题面

An instruction bus error in the Ibex instruction-fetch path can be misclassified when it occurs on a 32-bit instruction that starts at a half-word-aligned address, so the instruction spans two 16-bit halves across fetch words. In that case, the fetch logic may treat the faulting instruction as if the first half were a completed 16-bit RISC-V compressed instruction, advance the instruction stream by 2 bytes, and, when SecureIbex's sequential program-counter check is enabled, raise a spurious PC mismatch alarm. The correct behavior is that a fetch error must not cause that unaligned 32-bit instruction to be treated as compressed: the instruction must remain incomplete until both halves are available, and the next sequential PC tracked by the fetch path must advance by 4 bytes rather than 2. This affects the instruction fetch FIFO/front-end and is triggered by a sequential instruction bus error during an unaligned 32-bit instruction fetch.
