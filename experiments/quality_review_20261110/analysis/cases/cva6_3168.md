## 原始 HWE 题面

## Description
CVA6 can lose forward progress when the CV-X-IF interface for custom extensions is enabled while the RVC extension, the RISC-V compressed-instruction extension, is disabled. In this configuration, the Decode stage can still let the CV-X-IF compressed-instruction path affect instruction decoding even though compressed instructions are not supported. The failure was observed during debug-sequence initialization, where the core freezes instead of continuing execution.

## Expected Behavior
When RVC is disabled, a fetched instruction must be handled as a normal 32-bit uncompressed instruction. Enabling CV-X-IF in that configuration must not block decode, prevent a valid decode result from being issued, change the forwarded 32-bit instruction value, or mark the instruction as compressed.

## Actual Behavior
With CV-X-IF enabled and RVC disabled, the Decode stage may incorrectly let the compressed-instruction path participate in decode. As a result, an ordinary 32-bit instruction can fail to produce a valid issued decode result or be treated as compressed, which causes the core to stop making forward progress.

## Affected Function
Decode-stage handling of the interaction between the normal instruction-decode path and the CV-X-IF compressed-instruction path.

## Trigger Condition
The bug is triggered when CV-X-IF is enabled in a CVA6 configuration that disables RVC, and the core decodes a regular 32-bit instruction, including early instructions seen during debug-sequence initialization.
