## 原始 HWE 题面

Ibex can apply a Physical Memory Protection (PMP) update one instruction late. When software writes a PMP address or configuration CSR so that the next instruction address becomes non-executable, the core may still fetch that next instruction and let it execute instead of faulting immediately. The expected behavior is that the updated PMP permissions take effect for the very next instruction fetch: if the next program counter is now blocked for execution, that instruction must not execute and the core must raise an instruction access fault at that program counter. This bug affects PMP-based instruction-fetch permission checking, and it is triggered by a PMP CSR write immediately followed by a fetch from the newly blocked address.
