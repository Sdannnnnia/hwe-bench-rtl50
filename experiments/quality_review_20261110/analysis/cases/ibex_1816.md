## 原始 HWE 题面

Reading the `cause` field of the RISC-V Debug Control and Status Register (`DCSR.cause`) can report the wrong reason for entering debug mode. In the failing behavior, Ibex records a single-step cause (`DBG_CAUSE_STEP`) even though debug mode was entered because of an external debug request (`debug_req_i`), which should be reported as `DBG_CAUSE_HALTREQ`. This affects the debug-entry cause recording logic in `ibex_controller`. The bug is triggered when the core decides to enter debug mode because `debug_req_i` is asserted, but `debug_req_i` is de-asserted before the later cycle that saves the cause into `DCSR.cause`; the issue was observed after a debug return instruction (`dret`) followed by immediate re-entry into debug mode. In that situation, `DCSR.cause` must still read back as `DBG_CAUSE_HALTREQ`, because the debug entry was caused by the halt request rather than by single-step execution.
