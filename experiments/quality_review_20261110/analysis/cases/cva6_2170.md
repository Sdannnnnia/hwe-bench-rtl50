## 原始 HWE 题面

## Description
In 32-bit CVA6 configurations, the write-back data cache does not correctly format certain uncacheable stores when the AXI data bus is 64 bits wide. A 32-bit store to an uncacheable memory region can be acknowledged on AXI, but the target peripheral still does not observe the write, so the access appears to be lost.

## Expected Behavior
CVA6 must preserve 32-bit store semantics even when the write-back cache interfaces with a 64-bit AXI data bus. For an uncacheable 32-bit store, the request must be forwarded to AXI as a real write to the target peripheral, with the write data and byte strobes placed on the 32-bit lane selected by the address within the 64-bit AXI beat.

## Actual Behavior
With the write-back cache enabled, the AXI-side formatting for these uncacheable 32-bit stores uses the wrong 32-bit lane. As a result, the AXI transaction is acknowledged, but the write data or strobes are misaligned within the 64-bit beat and the intended peripheral write does not occur.

## Affected Function
The affected logic is the write-back data-cache control path that converts 32-bit CVA6 memory requests into 64-bit AXI write transactions for uncacheable accesses.

## Trigger Condition
This occurs when CVA6 is configured with XLEN=32, the write-back data cache is enabled, the AXI data bus is 64 bits wide, and software performs an uncacheable 32-bit store whose address selects a specific 32-bit lane within the 64-bit AXI beat, including the upper 32-bit half.
