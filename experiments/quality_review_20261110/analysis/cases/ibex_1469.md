## 原始 HWE 题面

When `BranchPredictor=1`, Ibex can mis-handle recovery from a branch that was predicted taken but later resolves as not taken if that branch is still unresolved while fetch continues down the predicted path. In the reported failing case, a preceding load delays resolution of the first branch, a later branch or jump on the speculative path is also predicted, and the recovery state for the earlier branch is replaced by the later prediction. Instructions from the wrong path can also remain buffered in the instruction fetch pipeline. When the earlier branch is finally resolved as not taken, the core can resume from the wrong PC and continue with wrong-path instructions, which can send execution into an unintended instruction stream and make the core appear to lock up. The expected behavior is that a predicted-taken branch that resolves as not taken must restart execution from the instruction immediately following that branch, independent of any later predictions, and any buffered instructions from the wrong predicted path must be discarded. This affects the instruction-fetch branch prediction and not-taken mispredict recovery logic.
