## 原始 HWE 题面

## Description
CVA6 uses a shared translation lookaside buffer (shared TLB) to cache page translations and refill the instruction and data TLBs. The shared TLB lookup can report a hit even when no single cached entry matches the entire request. If one way in a set matches the requested virtual page and a different way matches the requested address-space identifier (ASID), the lookup can incorrectly treat that as a valid hit and return a translation from the wrong address space.

## Expected Behavior
A shared TLB hit is valid only when one cached entry matches all lookup fields for the current request. At minimum, the requested virtual page and the ASID must match in the same entry; if additional virtualization qualifiers are enabled for that translation context, those qualifiers must also match in that same entry. If no single entry satisfies the full lookup, the shared TLB must miss so that CVA6 refills the instruction or data TLB from the correct translation.

## Actual Behavior
The lookup can combine partial matches from different ways in the same set and report a false hit. As a result, CVA6 can return a cached translation even though the ASID of the request does not match the entry that supplied the translation.

## Affected Functionality
Shared TLB hit-detection and tag-match logic in the CVA6 memory-management unit (MMU), specifically the logic that decides whether a cached translation can be used to refill the instruction-side or data-side TLB.

## Trigger Condition
The bug appears when a shared-TLB set contains multiple valid entries with different ASIDs. A concrete failing case is: one way holds virtual page X for ASID 0, another way in the same set holds a different virtual page for ASID 1, and a lookup is performed for virtual page X under ASID 1. That lookup must miss because no single entry matches both X and ASID 1, but the buggy logic can report a hit.
